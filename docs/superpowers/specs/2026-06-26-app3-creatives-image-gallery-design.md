# App3 /creatives — грид баннеров в истории + плашка retention

Дата: 2026-06-26
Статус: дизайн утверждён, ожидает реализации (TDD)

## Проблема

На странице App3 `/creatives` завершённая задача отдаёт только ссылку на
ZIP-архив. Индивидуальные PNG-баннеры уже копируются в `results/{uid}/` и
раздаются через StaticFiles, но в UI их нельзя посмотреть как картинки.
Пользователь хочет видеть все креативы изображениями, сгруппированными по
своему запросу, чтобы они не висели «все сразу от разных задач», а
открывались по клику.

## Решение (подход A — список картинок в существующем `/api/tasks`)

Один бэкенд-пробел: нет API, перечисляющего файлы по задаче. Закрываем,
расширяя существующий `GET /api/tasks` полем `images` — без новых
эндпоинтов и без второго round-trip при раскрытии аккордеона.

### Объём (подтверждено с пользователем)

- Грид — только 12 финальных баннеров. Hero-исходники не показываем.
- Клик по миниатюре → PNG в полном размере в новой вкладке (без отдельного
  lightbox-компонента).
- Грид показывается для ВСЕХ done-задач в истории (до 100), но свёрнут;
  `<img>` рендерятся лениво при первом раскрытии строки.
- Взаимодействие: строки задач свёрнуты, клик по заголовку раскрывает грид
  (аккордеон).
- Назначение — собственная страница App3 `/creatives` (не кросс-апп загрузка
  в App1).

## Бэкенд

### `app/api/schemas.py`
- `TaskOut`: добавить поле `images: list[str] = []`.

### `app/api/routes_tasks.py`
- `list_tasks` / `get_task` собирают список картинок и передают в `_task_out`
  (или `_task_out` принимает `results_dir`). Для `status == "done"`:
  `sorted((results_dir/uid).glob("*.png"))`, исключив `*.zip`, → относительные
  URL `/results/{uid}/{name}`. Для прочих статусов — `[]`.
- Источник списка — файловая система (glob), а не `meta`: список
  самовосстанавливающийся — после 24h-purge файлов нет → `images == []`, без
  битых ссылок.
- Порядок: имена zero-pad (`01_photo`, `02_render`, …) → `sorted` даёт
  корректный порядок баннеров.
- `results_dir` берётся из работающего сервиса:
  `request.app.state.creatives.results_dir` (тот же Path, что использует
  `creatives.py::_collect_results`). В тестах — подменяется фикстурой.

### `app/api/routes_pages.py`
- В context шаблона добавить `retention_hours = settings["retention_ttl_sec"] // 3600`.

## Фронтенд

### `app/templates/creatives.html`
- В шапке панели «Последние креативы» — строка-подсказка:
  «История и файлы хранятся {{ retention_hours }} ч, затем удаляются».
  Текст подставляется из конфига (не хардкод).
- CSS: `.task-grid` (CSS grid, ~3–4 миниатюры в ряд), `.task-thumb`
  (миниатюра баннера 300×600, object-fit), курсор-pointer на кликабельной
  строке.

### `app/static/creatives.js`
- `taskRow(t)`: если `t.images` непустой — заголовок строки кликабелен
  (аккордеон). Под строкой контейнер `.task-grid` со скрытым (`hidden`)
  состоянием. Клик по заголовку: при первом раскрытии лениво создать
  `<a target="_blank" href=prefix+url><img src=prefix+url class="task-thumb"></a>`
  для каждого url из `t.images`, затем togg-лить `hidden`.
- ZIP-ссылку в строке сохранить как есть.
- `onDone(d)`: после установки ZIP-ссылки вызвать `loadRecentTasks()`, чтобы
  свежезавершённая задача появилась в истории уже с гридом (файлы на диске к
  моменту `done`).
- Префикс URL (`window.APP_PREFIX`) применять к image-URL так же, как к ZIP.

## Без изменений

SSE-прогресс, обе HITL-паузы, `_collect_results`, StaticFiles-маунт
`/results`, retention-loop.

## Тесты (TDD)

### `tests/` — routes_tasks
- done-задача с N PNG в `results/{uid}/` → `/api/tasks` отдаёт `images`
  длины N в правильном порядке.
- ZIP (`{uid}.zip`) НЕ попадает в `images`.
- не-`done` задача → `images == []`.
- после удаления файлов из `results/{uid}/` → `images == []` (без битых
  ссылок).

### Фронт
- JS-логику аккордеона без юнит-теста (нет JS-харнесса) — проверка вручную
  + e2e прогон.

## Риски / заметки

- Glob по ФС в list-эндпоинте для ≤100 задач — локальный диск, малые
  директории; приемлемо.
- Ленивый рендер обязателен: 100×12 `<img>` сразу — недопустимая нагрузка на
  DOM.
