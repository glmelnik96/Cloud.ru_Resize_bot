# M3.2 — Figma MCP fill_templates_per_format design

**Status:** approved 2026-06-04, ready for implementation plan.

**Scope:** заменить PIL-stub в `graph/nodes/fill_templates_per_format.py` на реальную раскладку одного hero-визуала + текста в N мастер-фреймов через Figma MCP, экспортнуть каждый фрейм PNG'ом в `/data/renders/`. `render_all` (ZIP) — без изменений.

**Non-goals:**

- A/B-варианты (`__alt__` фреймы) — отложено с M3.1, в M3.2 не входит.
- Body-текст — реальные шаблоны Cloud.ru его не содержат, не вводим.
- Figma REST `/v1/images/?ids=...` — не используем, `get_screenshot` MCP покрывает экспорт.
- Cloudflare Tunnel / S3 hosting hero-картинки — не нужны, MCP `upload_assets` принимает байты.
- Изменения структуры графа LangGraph — нода остаётся на том же месте, контракт `state.image` (in) / `state.rendered_files` (out) сохраняется.

## 1. Контекст и решения брейншторма

### 1.1 Архитектурная развилка по hero-hosting (закрыта)

Изначально (OQ-01, июнь 2026) планировался вариант A: Figma Make MCP + Cloudflare Tunnel для public URL. После проверки фактического Figma MCP на `127.0.0.1:3845/mcp` (Desktop Figma + ml-cloud org, expert seat) выяснилось:

- `upload_assets` принимает **raw bytes** через POST на single-use upload URL + сразу ставит fill на указанный `nodeId`. Tunnel и S3 не нужны.
- `use_figma` исполняет JavaScript через Figma Plugin API. Текст-замены делаются через `figma.getNodeById(...).characters = "..."`.
- `get_screenshot` экспортит ноду в PNG (до 65536px по длинной стороне), отдаёт short-lived URL.

Это удаляет из плана июня: tunnel-инфру (фрагильность сессии), S3-сетап (которого нет), recon-style auth (auth берётся из залогиненного Desktop Figma). MCP видит залогиненного `gmmelnikov@sc.link` (ml-cloud org, expert seat) — подтверждено через `whoami`.

### 1.2 Связывание content↔ноды (L1 = JSON-манифест)

Реальные шаблоны не следуют spec'у `docs/figma_template_spec.md` (`{{slogan}}/{{body}}/{{cta}}/{{hero_image}}` naming). Они — реальные брендовые дизайны Cloud.ru с собственными layer-именами. Гнуть дизайны под spec — большая ручная работа дизайнера и потеря дизайн-решений, которые уже работают.

Выбран **JSON-манифест в репо** (`config/figma_templates.json`) — mapping `slug → frame_id → {slogan_text_id, hero_image_id, cta_text_id}`. Версионируется в git, новые фреймы = PR в манифест. Designer оставляет дизайны как есть.

Отвергнуты:
- Переименование слоёв под spec — ломает дизайнерскую свободу.
- PluginData-теги (`setPluginData("ad_role", "slogan")`) — невидимы в Figma UI, не дебажатся визуально, требуют custom tagging-UX.

### 1.3 Slogan split (L2 = одна строка)

В новых шаблонах (`3302:516`, `3302:401`) slogan лежит в одной text-ноде `Title`. Figma делает line-wrap сама. Никакого `slogan_lines: list[str]` в `MessageCandidate` вводить не нужно. `winner.slogan` идёт целиком в одну text-ноду.

### 1.4 Body / CTA в M3.2 (L3 = M1+CTA)

- **Body** — не вводим, в шаблонах его нет.
- **CTA** — есть в виде text-ноды внутри `Tag`-rounded-rectangle (фрейм `Logo Area`). `winner.cta` подставляется через `set_texts`. Если у конкретного шаблона нет CTA-ноды (`cta_text_id: null` в манифесте) — CTA-fill пропускается.

### 1.5 Сетевой контракт бот↔MCP (L4 = host.docker.internal)

Бот живёт в Docker, MCP — на хосте `:3845`. В `docker-compose.yml` сервису `bot` добавляется `extra_hosts: ["host.docker.internal:host-gateway"]`. Поддерживается Docker Desktop Win/Mac и Docker Engine 20.10+.

## 2. Архитектура

### 2.1 Высокоуровневый поток

```
generate_image (M3.1) → image_hitl → fill_templates_per_format (M3.2) → render_all (M3.0)
                          ↑                      ↓
                          hero PNG              N×format PNGs
                          + winner text
```

Внутри `fill_templates_per_format` для каждого `slug ∈ brief.formats`:

1. Find manifest entry by slug. Miss → PIL-fallback для этого формата, лог `manifest_miss_pil_fallback`, остальные форматы продолжают.
2. `upload_assets(file_key, nodeId=hero_image_id, bytes=hero_png)` — заливает hero как fill.
3. `use_figma(file_key, code=...)` — один JS-вызов: `getNodeById(slogan_id).characters = slogan_text`; если есть cta_id — то же для CTA. Один round-trip вместо двух.
4. `get_screenshot(file_key, nodeId=frame_id, maxDimension=max(W,H))` → short-lived PNG URL.
5. `httpx.get(url, timeout=30)` → запись в `/data/renders/{session}_{slug}_{ts}.png`.

После цикла: `return {"rendered_files": [{"format": slug, "path": str}, ...]}`. Длина массива = `len(brief.formats)` всегда (PIL-fallback заполняет недостающее).

### 2.2 Изоляция и lock-семантика

- Один Phygital-семантически: hero генерируется **один раз** на /new (см. `memory/project_one_creative_many_resizes.md`), переиспользуется на все форматы.
- Per-format MCP-операции (upload+set_texts+export) держат `asyncio.Lock` внутри `infra/figma_mcp.py`. Lock защищает от race между параллельными `/new` сессиями (whitelist=1 пока, но Lock дешёвый — 5 строк, ставим сразу).
- Между Phygital lock и Figma lock зависимости нет — это разные узлы графа, разные ресурсы.

### 2.3 Hard timeout

`asyncio.timeout(180.0)` на всю ноду. До 10 форматов × ~3.5s каждый = ~35s base, ×5 запас на медленный MCP / большие фреймы. По выходу таймаута — недорендеренные форматы дополняются PIL-fallback'ом в финальном sweep'е.

## 3. Компоненты

### 3.1 `config/figma_templates.json` — манифест

```json
{
  "file_key": "aZQYa8ye6EQj5WzjXAdQvC",
  "templates": {
    "vk_post_1080x1080": {
      "frame_id": "3302:516",
      "width": 1080,
      "height": 1080,
      "slots": {
        "slogan_text_id": "3302:520",
        "hero_image_id": "3302:522",
        "cta_text_id": null
      }
    }
  }
}
```

**Решения:**
- `cta_text_id: null` допустимо — шаблон без CTA рендерится корректно, CTA-fill пропускается.
- Slug — свободный, не следует regex'у `<channel>_<W>x<H>` из текущего кода. Текущий `_FORMAT_RE` в `fill_templates_per_format.py` **удаляется** — размер берётся из манифеста (`width`, `height`), не парсится из slug'а.
- Slug — единица контракта между `parse_brief` (LLM кладёт в `brief.formats`) и манифестом. `prompts/parse_brief.md` обновляется: список разрешённых слагов = ключи манифеста, LLM ограничен whitelist'ом.

Манифест укомплектовывается через bootstrap-helper (см. 3.4) для всех актуальных шаблонов перед деплоем M3.2 — пустых slots в продакшен-конфиге быть не должно.

**Pydantic-модели** (живут в `infra/figma_mcp.py` — они инфра-bound, не часть state):

```python
class FigmaSlots(BaseModel):
    slogan_text_id: str
    hero_image_id: str
    cta_text_id: str | None = None

class FigmaTemplate(BaseModel):
    frame_id: str
    width: int
    height: int
    slots: FigmaSlots

class FigmaManifest(BaseModel):
    file_key: str
    templates: dict[str, FigmaTemplate]
```

### 3.2 `infra/figma_mcp.py` — клиент

Async-обёртка вокруг Python `mcp` SDK (`streamable_http` transport). Singleton holder в духе `infra/phygital_client.py`:

```python
async def start_figma_mcp_client() -> FigmaMCPClient | None: ...
async def stop_figma_mcp_client() -> None: ...
def get_client() -> FigmaMCPClient | None: ...

class FigmaMCPClient:
    _lock: asyncio.Lock

    async def upload_hero(
        self, *, file_key: str, node_id: str, png_bytes: bytes
    ) -> None: ...

    async def set_texts(
        self,
        *,
        file_key: str,
        replacements: list[tuple[str, str]],  # [(node_id, text), ...]
    ) -> None: ...

    async def export_frame(
        self, *, file_key: str, node_id: str, max_dim: int
    ) -> bytes: ...
```

**Bootstrap:** `start_figma_mcp_client()` в `bot/app.py::_post_init` (рядом с `start_phygital_client`). Если `FIGMA_MCP_URL` не задан / health-check падает → возвращаем None, `fill_templates_per_format` детектит и идёт в полный PIL-fallback. Сохраняет dev-режим без MCP.

**Connection target:** `FIGMA_MCP_URL=http://host.docker.internal:3845/mcp` в `.env`.

### 3.3 `graph/nodes/fill_templates_per_format.py` (переписан)

PIL-композит сохраняется как **fallback-функция** `_pil_compose(...)`. Вызывается когда:
- `get_client() is None` (full-PIL-fallback на весь нод).
- `manifest.templates.get(slug) is None` (per-format fallback).
- MCP-вызов внутри per-format try/except упал (per-format fallback с `note=stub:figma_error:{type}`).

Контракт state — без изменений (см. raw stub в `graph/nodes/fill_templates_per_format.py`).

### 3.4 `scripts/figma_dump_structure.py` — bootstrap-помощник

Запускается оператором (Глебом), не ботом. Один `use_figma` JS-call: проходит по `figma.getNodeById(<page_id>).children` (только `FRAME`), собирает `[{id, name, width, height, children:[{id, name, type}], ...]`. Возвращает JSON, из которого по эвристике (имя содержит `Title` → slogan; имя содержит `Screenshot`/`image` → hero; `Tag`/`Button` внутри `Logo Area` → CTA) заполняется `config/figma_templates.json`.

Этот же скрипт может валидировать существующий манифест — проверять что все node_id из `slots` реально существуют в файле.

### 3.5 `docs/figma_template_spec.md` (переписан)

Старая версия (про `{{slogan}}/{{body}}/{{cta}}/{{hero_image}}` naming) не отражает реальность дизайна. Новая версия — manifest-flow:
- Designer создаёт фрейм с любой структурой, наслаждается свободой layer-имён.
- Минимум обязательного на фрейм: одна text-нода под slogan, одна image-fillable нода под hero, опционально text-нода под CTA.
- Designer (или Claude через `scripts/figma_dump_structure.py`) добавляет запись в манифест.
- Slug — свободный, но должен попасть в whitelist для `parse_brief`.

Старая версия архивится в `docs/archive/figma_template_spec-2026-06-04-pre-m3.2.md`.

## 4. Error handling

| Класс | Симптом | Реакция | Алерт админу |
|---|---|---|---|
| **MCP unreachable на boot** | `start_figma_mcp_client()` → None | Лог `figma_mcp_unavailable`; `get_client()` всегда None; нод делает full-PIL-fallback на все форматы | Boot: один warning-лог, без TG. Первый `/new` после: `figma_mcp_unavailable_full_fallback` лог |
| **MCP жил, но запрос упал** | `upload_assets`/`use_figma`/`get_screenshot` raise | per-format except → PIL-fallback для этого формата, остальные продолжают | `notify_admin("figma_mcp_dead", ..., dedupe_key="figma_mcp_dead", cooldown_s=3600)` — реюз `infra/admin_alert.py` из P0.2.5 |
| **Slug нет в манифесте** | `manifest.templates.get(slug) is None` | per-format PIL-fallback, лог `manifest_miss_pil_fallback` | Нет — это контентная ошибка `parse_brief`, не инфра |
| **Hero local_path не существует** | `Path(local_path).read_bytes()` → FileNotFoundError | `raise ValueError` из всего ноды (это уже баг state pipeline'а, должен валиться громко) | Нет |
| **Манифест не парсится / file_key пустой** | JSON broken / file_key=="" | На boot: лог-error, `get_client()` → None, full-PIL-fallback в рантайме | На boot: `notify_admin("figma_manifest_broken", ...)` один раз |
| **fileKey невалидный (404 от Figma)** | upload_assets/get_screenshot → 4xx | per-format PIL-fallback с specific error_type в note | Через `figma_mcp_dead` dedupe_key |
| **Hard timeout на нод (180s)** | `asyncio.timeout` срабатывает | Финальный sweep: недорендеренные форматы → PIL-fallback | Нет (нормальный recovery path) |

**Timeouts внутри клиента:** `httpx.AsyncClient(timeout=30.0)` per MCP-request. MCP типично отвечает <2s, `get_screenshot` для тяжёлого фрейма может быть 5-15s, 30s — нормальный hard limit.

**Логи (event-prefix `figma_*`):**
- `figma_mcp_ready` / `figma_mcp_unavailable` (boot)
- `figma_format_ok` (per format, с `slug`, `latency_ms`)
- `figma_format_fallback` (per format, с `slug`, `reason`, `error_type`)
- `figma_node_done` (после всех форматов, с `n_total`, `n_real`, `n_fallback`, `node_latency_ms`)

### 5.2 Integration-test (gated)

`tests/integration/test_figma_mcp_live.py` — запускается **только** при `RESIZE_BOT_E2E_FIGMA=1`:
- bot контейнер поднят
- Figma desktop залогинен, MCP жив на 3845
- манифест укомплектован

В CI не гоняется (нет залогиненной Figma). Локально перед мержем M3.2 — запускается руками.

### 5.3 Smoke-чеклист (оператор после деплоя)

1. `scripts/figma_dump_structure.py` → JSON структуры `play ground`.
2. `config/figma_templates.json` заполнен для всех актуальных шаблонов.
3. `.env`: `FIGMA_MCP_URL=http://host.docker.internal:3845/mcp`.
4. `docker-compose.yml`: `extra_hosts: ["host.docker.internal:host-gateway"]` для сервиса `bot`.
5. `docker compose up -d --build bot`.
6. В логах boot найти `figma_mcp_ready` с положительным health-check'ом.
7. `/new` с brief'ом и слагами из манифеста → ZIP содержит реальные рендеры Figma.
8. `/new` с одним слагом-не-из-манифеста → этот формат — PIL-stub, остальные real.

### 5.4 Acceptance criteria

M3.2 закрыт когда:

- [ ] `/new` с реальным брифом и ≥2 формата → ZIP содержит N PNG из Figma (не PIL-stub).
- [ ] `FIGMA_MCP_URL=""` → `/new` всё ещё проходит, отдаёт PIL-stub'ы (graceful degradation).
- [ ] Slug не из манифеста → пропускается с PIL-stub, остальные форматы рендерятся.
- [ ] MCP таймаутит на одном формате → этот формат — PIL-stub, остальные нормально; в логах `figma_format_fallback`.
- [ ] Admin TG-алерт приходит при первом MCP-кризисе; дедуп 1ч работает.
- [ ] Все 10 unit-тестов проходят.

## 8. Открытые вопросы (не блокеры, фиксируем для memory)

- **OQ-06:** Что делать, если slogan длиннее, чем `Title` text-нода может вместить визуально (overflow)? Figma делает auto-shrink или просто обрезает? Для smoke — не блокер, мониторим визуально после первых рендеров.
- **OQ-07:** CTA-текст в `Tag` rounded-rectangle — это child text-нода, или text лежит на самом rect'е? Уточнится при bootstrap через `figma_dump_structure`.
- **OQ-08:** При параллельном `/new` (когда whitelist расширится) — Lock защищает от race внутри одного фрейма; но что с разными форматами в разных сессиях? Они пишут в разные ноды, не пересекаются — Lock per-frame, не глобальный? Сейчас Lock глобальный (5 строк проще), оптимизация — после реальной нагрузки.
