# M3.2 — Figma MCP write-flow: architecturally broken

**Status:** dead-end as of 2026-06-05. The infrastructure in `infra/figma_mcp.py`,
the per-format calls in `graph/nodes/fill_templates_per_format.py`, the manifest
in `config/figma_templates.json`, and the spec in `docs/figma_template_spec.md`
were all built against an assumption that does not hold.

## What we assumed

That the local Figma Desktop MCP server (`host.docker.internal:3845/mcp`)
exposes the write tools `upload_assets` (upload PNG → bind as image fill on a
node) and `use_figma` (run a JS snippet via the Plugin API to set
`.characters` on text nodes). The implementation was tested against fakes that
mirrored the schema of those tools as advertised by the cloud Figma MCP.

## What is actually true

1. **Local Figma Desktop MCP is Dev Mode — read-only.** It only exposes
   codegen-style tools: `get_design_context`, `get_metadata`, `get_screenshot`,
   `get_variable_defs`, `get_code_connect_map`, `add_code_connect_map`.
   Calling `upload_assets` or `use_figma` against it returns
   `Invalid tool arguments: invalid_union_discriminator` — the tool name is
   simply not in the union of accepted tools.

2. **Cloud Figma MCP (`mcp.figma.com`) does expose the write tools — but it
   is closed to third-party bots.** Access requires OAuth with the
   `mcp:connect` scope, which Figma whitelists to approved clients only
   (Claude Desktop, Cursor, etc.). Figma Personal Access Tokens are **not**
   accepted on the MCP endpoint. We cannot register Resize_bot for this scope.

3. Therefore the entire `FigmaMCPClient.upload_hero` + `set_texts` path is
   dead code: every per-format call will catch the MCP error and fall back to
   the PIL stub. The smoke run on 2026-06-05 confirmed this — every format in
   the ZIP was the blue-box PIL placeholder.

## Root cause

The spec was written from tool schemas in the Claude Code MCP registry without
running `session.list_tools()` against the actual target server. The mismatch
between "what some Figma MCP somewhere can do" and "what the server we connect
to actually exposes" was never checked. Don't repeat the mistake — for any
future MCP integration, the first concrete step is to enumerate tools against
the live endpoint and pin the spec to that list.

## What survives M3.2

- The **manifest principle** (`config/figma_templates.json` binding slots by
  node_id, not by layer-name convention) is still the right design. See
  `feedback_figma_manifest_flow.md` in agent memory.
- The **per-format loop** in `fill_templates_per_format.py` with PIL fallback,
  debounced admin alerts, and 180s timeout is reasonable scaffolding.
- The **wizard / graph / HITL / ZIP** layers are untouched by this issue.

## What needs redesign

The rendering backend in `fill_templates_per_format` and the contents of the
manifest's `slots.*` block. Three options, in order of recommended-ness:

- **D (recommended).** Drop Figma from the runtime. Designer exports each
  master frame once as a layered PSD (or a folder of layered PNGs with a
  small JSON describing rects/fonts). The bot composites slogan / CTA / hero
  with Pillow at request time. Manifest stays, slot binding stays, only the
  rendering backend changes.
- **E.** Ship a custom Figma plugin that the designer runs on their machine;
  the plugin polls a queue and returns PNGs. High operational friction;
  only worth it if designer-in-the-loop is actually a feature.
- **B.** Keep the read-only Desktop MCP for `get_screenshot` of the unedited
  frame and overlay with PIL on top. Pointless unless we also need live Figma
  reads for something else.

The next conversation step is a top-down architectural review of the whole
bot — module by module, inputs / outputs — before picking one of the above.

## Files in scope (kept in place, not reverted)

- `infra/figma_mcp.py` — `FigmaMCPClient.upload_hero` / `set_texts` / `export_frame`
- `graph/nodes/fill_templates_per_format.py` — per-format MCP call + PIL fallback
- `config/figma_templates.json` — manifest with Figma node_ids in slots
- `docs/figma_template_spec.md` — spec for the broken flow
- `scripts/figma_dump_structure.py` — bootstrap helper for adding a slug
- `tests/integration/test_figma_mcp_node.py` — passes against fakes; does not
  exercise a real MCP

Leaving them in place rather than reverting because the surrounding wiring
(graph node shape, manifest plumbing, debounced alerts, lifecycle hooks)
will likely be reused by whatever replaces the MCP backend.
