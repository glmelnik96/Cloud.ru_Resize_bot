# Evolution Managed RAG

## Блок 1. Описание продукта

### Что такое Evolution Managed RAG (core-сущность продукта)

Evolution Managed RAG - облачный сервис для создания базы знаний и генеративного поиска по корпоративным документам. Сервис подготавливает загруженные материалы для семантического поиска, находит релевантный контекст и передает его языковой модели. Пользователь получает ответ, основанный на актуальной версии корпоративных данных, без самостоятельной сборки векторной базы и RAG-инфраструктуры.

Корпоративные знания становятся доступным контекстом для ИИ-приложений.

### Основные возможности (дают основную ценность)

• Создание баз знаний. Документы загружаются в Evolution Object Storage, после чего сервис подготавливает их для семантического поиска. Команде не нужно отдельно собирать процесс индексации.
• Версионирование. Новые данные можно добавлять и обновлять с контролем версий. Команда понимает, какой набор материалов использует приложение, и может вернуться к предыдущей версии.
• Поиск в векторном пространстве. Сервис сопоставляет запрос со смыслом фрагментов, а не только с совпадением ключевых слов. Это повышает релевантность при работе с неструктурированными текстами и разными формулировками одного вопроса.
• Интеграция через API. За один запрос приложение может получить найденные документы и итоговый ответ модели. RAG встраивается в чат, портал, службу поддержки или другой пользовательский интерфейс.
• Выбор модельного слоя. Для генерации ответа можно использовать модели Evolution Foundation Models или собственную модель, развернутую в Evolution ML Inference.
• Управление источником данных через S3. Клиент обновляет документы в Evolution Object Storage и сохраняет контроль над составом корпоративной базы знаний.

### Добавленная стоимость (дополнительные преимущества)

• Готовая RAG-инфраструктура убирает необходимость выбирать, развертывать и сопровождать отдельную векторную базу, индексатор и сервис поиска.
• Разделение базы знаний и языковой модели сохраняет архитектурную гибкость: данные можно обновлять независимо от выбранной модели.
• Версионирование делает изменения контролируемыми и упрощает проверку качества перед публикацией новой базы знаний.
• API возвращает не только готовый ответ, но и релевантные документы. Приложение может показывать пользователю источники или передавать их на дополнительную проверку.
• Интеграция с Foundation Models и ML Inference позволяет начать с готовой модели, а затем перейти к собственному endpoint без перестройки базы знаний.
• Сервис использует средства шифрования Cloud.ru и рассчитан на работу с корпоративными данными в облачной инфраструктуре Evolution.

## Блок 2. Описание задач

### Какие проблемы закрывает

• Документы распределены по папкам и хранилищам, а сотрудники формулируют один вопрос разными словами. Семантический поиск находит подходящие фрагменты по смыслу.
• Обычная языковая модель отвечает из общих знаний и может придумывать детали. RAG передает модели найденный корпоративный контекст и ограничивает ответ материалами базы знаний.
• Информация меняется, но приложение продолжает использовать старый индекс. Версионирование помогает управлять обновлениями и возвращаться к проверенной версии.
• Команда тратит время на сборку векторной базы, разбиение документов и интеграцию компонентов. Managed RAG предоставляет готовый сервис подготовки данных и поиска.
• В корпоративном архиве есть сканы и изображения без текстового слоя. Такие материалы сначала нужно распознать отдельным OCR- или VLM-компонентом, после чего извлеченный текст можно включить в базу знаний.
• Пользователю нужен не только ответ, но и основание для проверки. API может вернуть релевантные документы вместе с финальным ответом.
• Разные команды выбирают разные модели. Отдельный модельный слой позволяет использовать Foundation Models или собственную модель из ML Inference с одной базой знаний.

### Сценарии применения (типовые)

• Внутренний ассистент по базе знаний. Сотрудник задает вопрос в корпоративном чате и получает ответ по актуальным инструкциям, политикам и рабочим материалам.
• Помощник службы поддержки. Оператор или клиентский бот находит сведения о продукте, условиях и процедурах и использует их при подготовке ответа.
• Техническая база знаний. Инженер ищет сведения по оборудованию, API, эксплуатации или устранению неисправностей без точного знания названия документа.
• Смешанный документный архив. Текстовые документы и результаты предварительного OCR для сканов объединяются в одну базу знаний с контролем версий.
• Поиск по юридическим и нормативным материалам. Специалист находит связанные положения в договорах, политиках и регламентах и проверяет исходные документы.
• Корпоративный ассистент для ритейла или производства. База знаний объединяет сведения о товарах, внутренних процедурах, оборудовании и поддержке сотрудников.
• База знаний для ИИ-агента. Evolution AI Agents получает корпоративный контекст из Managed RAG перед анализом задачи или обращением к инструментам.

### Отрасли, где ценность проявляется быстрее

• Ритейл и FMCG. База знаний объединяет сведения о товарах, доставке, возвратах, поддержке и внутренних процессах для сотрудников и клиентских интерфейсов.
• Производство, инжиниринг и агропромышленный сектор. Инженеры и специалисты получают доступ к руководствам, стандартам, журналам и технической документации.
• Финансы и страхование. Большой объем регламентов, продуктовых условий и документов требует поиска по актуальным версиям и возможности проверить источник ответа.
• IT и разработка. Команды создают поиск по архитектурным решениям, API, runbook, базе инцидентов и внутренней документации.
• Госсектор и регулируемые отрасли. Сервис подходит для навигации по нормативным материалам и внутренним инструкциям в корпоративной облачной среде.
• HR, обучение и корпоративные функции. База знаний поддерживает онбординг и ответы по политикам, процессам и учебным материалам.

## Блок 3. Описание аудитории

### Аудитория 1. Владельцы баз знаний, поддержки и корпоративных функций

Что хотят: сократить время поиска, дать сотрудникам единый способ получать ответы и управлять актуальностью материалов.
Что предлагаем: создание и версионирование баз знаний, семантический поиск и API для подключения к внутреннему порталу, чату или сервису поддержки.

### Аудитория 2. AI Head, CIO и руководители ИИ-направлений (ЛПР)

Что хотят: запускать прикладные сценарии на корпоративных данных без сборки собственной RAG-платформы и сохранять выбор модели.
Что предлагаем: управляемую RAG-инфраструктуру, работу с данными в Evolution Object Storage и совместимость с Foundation Models и ML Inference.

### Аудитория 3. Архитекторы и специалисты по интеграции

Что хотят: встроить генеративный поиск в существующие системы, контролировать версии данных и разделить слои хранения, поиска и генерации.
Что предлагаем: API, возвращающий релевантные документы и ответ модели, версионирование базы знаний и отдельный выбор модельного endpoint.

### Аудитория 4. Разработчики и AI-инженеры (ЛВР и пользователи)

Что хотят: быстро добавить RAG в приложение, не поддерживать векторную базу и тестировать разные модели на одной базе знаний.
Что предлагаем: готовый процесс подготовки документов, векторный поиск, API-интеграцию и подключение моделей из Foundation Models или ML Inference.
