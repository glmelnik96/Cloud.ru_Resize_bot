# Evolution Foundation Models

## Блок 1. Описание продукта

### Что такое Evolution Foundation Models (core-сущность продукта)

Evolution Foundation Models - сервис единого доступа к готовым ИИ-моделям разных классов и поставщиков через OpenAI-совместимый API. Команда подключает модели к приложениям, корпоративным чатам и инструментам разработки без отдельной интеграции с каждым поставщиком и без самостоятельного развертывания каждой модели. Часть моделей работает в инфраструктуре Cloud.ru, часть доступна через внешних провайдеров, поэтому условия размещения и обработки данных зависят от выбранной модели. По логике работы сервис близок к OpenRouter: он дает единый эндпоинт, API-ключ и формат запросов для выбора и подключения разных моделей.

Единый доступ к моделям разных поставщиков: от сравнения вариантов до интеграции в корпоративное приложение.

### Основные возможности (дают основную ценность)

• Каталог готовых моделей. Сервис объединяет модели, размещенные в инфраструктуре Cloud.ru, и модели внешних провайдеров. Команда выбирает вариант под задачу, требования к качеству, размеру контекста, стоимости и маршруту обработки данных.
• OpenAI-совместимый API. Приложения и фреймворки подключаются через единый эндпоинт и знакомый формат запросов. При смене модели не требуется заново проектировать интеграционный слой.
• Reasoning. Модели, которые поддерживают эту функцию, анализируют контекст и формируют выводы для задач, где недостаточно простого продолжения текста: диагностики, рекомендаций и разбора сложных запросов.
• Function Calling. Поддерживающие функцию модели формируют вызов функции или API в заданном формате. Это упрощает подключение прикладных сервисов и выполнение действий через программный код.
• Structured Outputs. Поддерживающие режим модели возвращают данные по заданной структуре. Результат можно передать в отчет, карточку, базу данных или следующий компонент приложения без ручного разбора свободного текста.
• Guardrails. Фильтр маскирует чувствительные данные до отправки запроса, а отдельный LLM-контроль проверяет входные и выходные данные на вредоносные инструкции. Эти механизмы добавляют слой контроля, но не заменяют выбор модели с подходящими условиями обработки данных.
• Тарификация по входным и выходным токенам. Команда видит стоимость обращения для выбранной модели и может сравнивать варианты на реальной нагрузке.

### Добавленная стоимость (дополнительные преимущества)

• Не нужно поддерживать отдельную интеграцию, учетную запись и формат запросов для каждого поставщика. Cloud.ru дает единую точку доступа и учета потребления.
• В одном сервисе можно выбирать между моделями, размещенными в инфраструктуре Cloud.ru, и внешними моделями. Для задач с требованиями к маршруту и размещению данных команда выбирает подходящий вариант или переходит к частному развертыванию в Evolution ML Inference.
• Для моделей в инфраструктуре Cloud.ru сервис берет на себя развертывание и сопровождение инференса. Доступ к внешним моделям предоставляется через тот же API, без отдельной интеграции с провайдером.
• Единый API снижает стоимость экспериментов: разработчики меняют модель и сравнивают результаты без переработки приложения.
• Практические руководства помогают подключить LibreChat, Open WebUI и Aider. Команда получает проверенную отправную точку для корпоративного чата и инструментов разработки.
• Сервис встраивается в экосистему Evolution. Модели можно использовать в Evolution Managed RAG и Evolution AI Agents, а для отдельного экземпляра выбранной модели перейти к Evolution ML Inference.

## Блок 2. Описание задач

### Какие проблемы закрывает

• Для проверки модельного подхода приходится выделять GPU, настраивать среду исполнения и поддерживать API. Готовый сервис убирает этот этап для моделей из каталога и оставляет команде работу с промптами, качеством и приложением.
• Разные поставщики используют отдельные точки подключения, ключи и правила интеграции. OpenAI-совместимый API создает единый слой доступа и упрощает сравнение альтернатив.
• Команде трудно выбрать баланс между качеством, размером контекста, стоимостью и условиями обработки данных. Единый каталог и тарификация по токенам позволяют тестировать варианты на одном наборе задач.
• Корпоративные политики различаются по допустимому маршруту данных. Сервис дает выбор между моделями в инфраструктуре Cloud.ru и внешними моделями; для строгих требований можно использовать подходящую модель или частное развертывание в Evolution ML Inference.
• Свободный текст неудобно передавать в корпоративные системы. Structured Outputs возвращает результат в заранее определенной структуре для моделей, которые поддерживают этот режим.
• Запросы могут содержать чувствительные данные или скрытые инструкции. Guardrails добавляет отдельный слой проверки до и после обращения к модели.
• Бизнес-пользователи применяют разные ИИ-сервисы без централизованного доступа. Foundation Models позволяет подключить корпоративный интерфейс к нескольким моделям через единый сервис.
• Успешный сценарий нужно перевести из личного эксперимента в повторяемый корпоративный процесс. Единый API помогает сохранить интеграционную схему при переходе от прототипа к внутреннему или клиентскому приложению.

### Сценарии применения (типовые)

• Ассистент разработчика. Выбранная модель объясняет и рефакторит код, помогает готовить тесты и документацию через совместимый инструмент разработки.
• Внутренний ИИ-ассистент. Корпоративный чат использует модель с подходящими условиями обработки данных для анализа запросов, подготовки черновиков и ответов сотрудникам.
• Анализ обращений и документов. Модель классифицирует текст, выделяет ключевые факты и возвращает структурированный результат для следующего этапа обработки.
• Модельный слой для корпоративной базы знаний. Evolution Managed RAG передает найденный контекст в Foundation Models и формирует ответ по внутренним документам.
• Анализ логов и инцидентов. Модель получает подготовленный контекст из системы наблюдаемости или поиска, группирует события и формирует сводку для проверки специалистом.
• Подготовка текстов. Команды создают черновики описаний, писем, отчетов и инструкций, затем проверяют их по корпоративным правилам.
• Модельный слой для ИИ-агента. Evolution AI Agents использует выбранную модель для анализа задачи и работы с подключенными знаниями и инструментами.

### Отрасли, где ценность проявляется быстрее

• IT, разработка и кибербезопасность. Команды подключают модели к инструментам работы с кодом, внутренним чатам, анализу логов и прототипам новых функций.
• Девелопмент, строительство и инжиниринг. Модели помогают разбирать проектные материалы, готовить технические тексты и поддерживать разработчиков цифровых сервисов.
• Ритейл и FMCG. Сервис подходит для внутренних ассистентов, анализа отзывов и обращений, подготовки карточек и коммуникаций.
• Производство. Модели применяются для анализа технических текстов, классификации обращений и подготовки структурированных материалов для специалистов.
• Финансы и страхование. Централизованный модельный API используют для анализа текстов, подготовки выводов и внутренних ассистентов с обязательной экспертной проверкой.
• Телеком и сервисные компании. Большой поток обращений создает спрос на классификацию, подсказки оператору и анализ коммуникаций.

## Блок 3. Описание аудитории

### Аудитория 1. AI Head, CIO и руководители ИИ-направлений (ЛПР)

Что хотят: предоставить командам управляемый доступ к разным моделям, контролировать расходы, сократить срок проверки гипотез и выбирать допустимый маршрут обработки данных.
Что предлагаем: единую точку доступа к моделям разных поставщиков, тарификацию по токенам, выбор между моделями в инфраструктуре Cloud.ru и внешними моделями, а также возможность подключить корпоративные интерфейсы вместо разрозненных сервисов.

### Аудитория 2. Архитекторы, платформенные команды и специалисты по безопасности

Что хотят: встроить модели в корпоративный ландшафт через стандартный интерфейс, сократить число интеграций и учитывать требования к маршруту данных для разных сценариев.
Что предлагаем: OpenAI-совместимый API, прозрачный выбор модели и варианта размещения, Guardrails и переход к отдельному экземпляру в Evolution ML Inference для сценариев с особыми требованиями к данным или производительности.

### Аудитория 3. Технические лидеры и разработчики (ЛВР)

Что хотят: быстро сравнивать модели разных поставщиков, подключать их к привычным библиотекам и получать структурированные ответы для приложений.
Что предлагаем: единый эндпоинт и API-ключ, обновляемый каталог без привязки архитектуры к одной модели, поддерживаемые моделью функции Reasoning, Function Calling и Structured Outputs, а также руководства по подключению совместимых инструментов.

### Аудитория 4. Владельцы цифровых продуктов и руководители бизнес-функций

Что хотят: встроить генеративный ИИ в поддержку, аналитику, работу разработчиков, контент или внутренние сервисы без отдельного договора и интеграции с каждым поставщиком моделей.
Что предлагаем: единый модельный API для пилота и промышленного приложения, выбор модели под задачу и требования к обработке данных, совместимость с Evolution Managed RAG и Evolution AI Agents.
